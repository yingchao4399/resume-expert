# 简历专家

基于目标岗位 JD 的个人简历优化工作台。项目会分析岗位要求、识别经历证据缺口、生成可核验的优化建议，并将最终简历保存为多个本地岗位版本。

当前版本：`v1.10.0`。本版本新增双模式 PDF 直接下载、自定义优化风格和可核验的缺失关键词增强流程。

## 已实现能力

- 材料 → 分析 → 制作 → 交付四阶段工作流，显示完成状态、阻塞原因和下一步入口
- 两阶段可信分析：先生成并人工确认 JD 需求地图，再匹配经历事实；两个任务分别支持实时心跳、主动取消和 2 分钟硬上限
- JD 决策地图保存原文跨度、原子要求、必须/优先/否定条件、优先级依据、岗位假设和质量风险
- 岗位准备度由 TypeScript 按要求优先级和可核验证据强度确定性计算，不使用模型自报总分
- 面试策略进入面试页后按需生成，不阻塞简历制作
- Mock / 真实大模型两种运行模式
- 按目标岗位保存、切换、重命名、复制和删除多个简历版本
- 浏览器本地自动保存，刷新或重新打开后继续使用
- 浏览器本地导入 PDF / DOCX、预览提取文本并可选 AI 结构化；支持工作、项目、多段教育、证书、语言、奖项和链接等资料
- 全局经历证据库：导入候选需人工确认，AI 改写保留来源关联
- 项目化经历事实库：工作、项目、实习、原子事实、量化证据和能力标签形成可追溯关联
- 自适应项目梳理：1–5 轮动态追问，候选事实必须保留用户原文引用并逐条确认
- 能力等级同时显示用户自评与 0–4 级确定性证据校验结果
- 自动证据匹配只生成候选，必须人工确认；人工改写或证据变化会要求重新核对
- 修改岗位、JD 或原简历后保留旧分析供查看，但锁定后续生成和交付，避免新旧材料混用
- 当前版本或完整文档库 JSON 备份、合并与替换恢复
- 三款 ATS 单栏模板及字体、间距、页边距、颜色、顺序和显隐设置
- 最终简历完整编辑，支持工作/项目经历和成果描述增删
- ATS 就绪度估算：关键词 40%、经历证据 30%、量化成果 20%、内容完整度 10%
- ATS 友好单栏 DOCX 下载，以及可搜索复制的 ATS 文字版 PDF
- 与 A4 预览一致的视觉还原版 PDF；A4 页面同时支持下载、系统打印、返回和关闭
- 按岗位版本保存的自定义优化风格，表达要求受事实与证据边界约束
- 可选缺失关键词增强：用户可核验采用、补正证据后采用或暂不采用，不强制补正才能继续
- 本地投递管理：准备中、已投递、笔试、面试、Offer、结束六种固定状态
- 独立面试复盘持久化，可关联投递记录和实际使用的简历版本
- 本地状态统计、面试率和 Offer 率（仅描述记录，不承诺因果）
- Zod 请求与模型输出校验；OpenAI 使用严格 JSON Schema
- 最终简历采用草稿 / 已确认 / 已过期状态，只有已确认版本可进入交付
- AI 设置支持保存前连接测试、15 秒测试超时和可操作的错误分类；一般正式请求 120 秒超时，结构分析单次请求限制为 60 秒
- 中文 PDF 使用本地 CMap/标准字体资源并按坐标重建行，分别提示扫描、加密和字体编码问题
- 面试录音支持浏览器定位播放与确认删除，删除后自动解除复盘元数据关联
- 损坏浏览器数据进入恢复模式：锁定自动覆盖，并提供下载、尝试恢复和确认清空
- 简历和排版草稿具备离开保护，顶部显示保存中、已保存时间或保存失败

## 快速开始

项目统一使用 Node.js 24 LTS、npm 和 `package-lock.json`。

```bash
npm install
npm run dev
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。开发服务器只绑定本机回环地址，同时允许 `127.0.0.1` 和 `localhost` 访问，不向局域网开放。

如果页面能显示但按钮没有反应，可运行下面的检查。它会验证首页以及页面引用的全部 Next.js 脚本，遇到假 200、403、404 或脚本缺失会直接失败：

```bash
npm run verify:local
```

如果当前终端找不到 `npm`，请先安装 Node.js 24 LTS，并重新打开终端。

## 使用流程

1. 新建一个简历版本，粘贴文本，或在浏览器本地导入 PDF / DOCX。
2. 在“经历证据库”核对导入候选；只有确认后的证据才会作为 AI 的额外事实来源。
3. 填写目标岗位和 JD 后点击“解析 JD”，在四个视图中核对原文、要求、推断和质量风险。
4. 批量确认有明确原文依据的安全项，逐条处理其余要求；确认整张需求地图后再点击“匹配真实经历”。
5. 查看岗位准备度、逐条证据强度与高价值缺口；它是准备决策工具，不代表录用概率，也不与 ATS 分混合。
6. 在“经历补证”中补充真实经历，生成的内容会先进入待确认证据；需要面试准备时进入对应页面按需生成。
7. 进入“制作”阶段，选择预设或自定义优化风格，再生成优化方案；缺失关键词增强可以全部跳过，也可以核验后直接采用或补正真实证据后采用。
8. 在“最终简历”中人工编辑、检查来源记录并统一模板排版。
9. 在“投递与进展”中记录状态、下一步日期和实际使用的简历。
10. 在“导出结果”中下载 DOCX、ATS 文字版 PDF 或视觉还原版 PDF，也可以打开 A4 页面使用系统打印；面试后可在独立复盘模块保存诊断。

顶部版本选择器用于管理不同岗位的简历。复制版本适合保留一份基础简历，再针对新的 JD 调整。

## Word 与 PDF

- DOCX 使用单栏正文、普通标题和项目符号，不使用表格、图片、图标或复杂分栏。
- ATS 文字版 PDF 使用矢量文本和本地嵌入的 Noto Sans SC 字体，可搜索、复制并适合 ATS 读取；字体遵循仓库内 `public/fonts/OFL.txt`。
- 视觉还原版 PDF 按网页 A4 页面逐页生成，优先保证模板、颜色、间距、区块顺序和分页与预览一致。
- 两种 PDF 均在浏览器本地生成，不上传或持久化二进制文件；仍可通过“系统打印”使用浏览器原生打印功能。
- 页面设置的 A4 页边距只由 `@page` 应用一次；例如设置 16 mm，打印 PDF 的实际内容边距即为 16 mm。
- 打印时建议关闭浏览器的页眉和页脚。
- ATS 分数是本地规则估算，用于发现内容缺口，不代表任何招聘系统的真实筛选结果。

## 大模型接入

未配置 API Key 时自动使用 Mock 模式，完整流程仍可体验。Mock 仅用于流程验证：除仓库内明确的示例数据外，它不会补造原始材料中不存在的人名、公司、日期或业绩数据，正式求职请配置并测试真实模型。

可以点击页面右上角“AI 设置”，也可以创建 `.env.local`：

```env
LLM_API_KEY=sk-xxx
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_PROVIDER=openai
```

API Key 输入框只粘贴服务商控制台生成的 Key 本身，不要包含“API Key：”、中文括号、说明文字或空格。格式错误时应用会自动回退 Mock，并要求重新填写。

设置页的“测试连接”会使用当前尚未保存的 Provider、Base URL、模型和 Key 发起最小请求，结果只返回分类和耗时，不会回显或记录 Key。认证、模型、地址、限流、网络和超时会分别提示。

“刷新可用模型”只在点击后访问当前兼容接口的 `/models`，区分官方预设与账号实际返回；刷新失败不会阻止手填模型 ID，也不会自动替换已经保存的旧模型。支持 DeepSeek、Kimi、通义千问、智谱、OpenAI、Gemini，以及自定义 OpenAI 兼容接口。

项目通过 OpenAI 兼容的 `/chat/completions` 接口调用模型。OpenAI Provider 使用严格 JSON Schema；DeepSeek、Kimi、通义、智谱、Gemini 等兼容 Provider 使用 JSON Object 模式并在 Prompt 中携带完整 Schema，所有结果统一经过 Zod 运行时校验。

DeepSeek V4 的结构抽取任务会显式关闭思考模式，以减少无效推理等待；这不会替换当前选择的模型。设置页仍推荐更快的 `deepseek-v4-flash`，用户选择的 `deepseek-v4-pro` 会原样保留。

模型返回无法解析或结构不合法时，系统只自动修复一次；再次失败会返回明确错误，不会把不完整数据写入简历。JD 解析与事实匹配各自最多运行 2 分钟、最多调用 Provider 6 次，单次结构请求最多 60 秒；JD 每批最多 16 条、匹配每批最多 12 条。取消、超时、截断重试耗尽或流意外中断都不会写入半成品。

## 数据与隐私

- 简历、投递和复盘保存在当前浏览器的 `localStorage` 中；项目化经历事实保存在独立 IndexedDB，均不会自动同步到云端。
- V8 JSON 备份会异步汇总 localStorage 与 IndexedDB，并保存完整导入资料、自定义风格、关键词增强草稿及核验状态，继续兼容 V1–V7。
- API Key 保存在本机项目目录的 `.ai-user-config.json` 中，该文件已被 Git 忽略。
- 使用真实大模型时，JD、简历和补充信息会发送给所配置的模型服务商。
- 清除浏览器站点数据会删除本地简历、证据库、投递与复盘记录，重要内容请及时导出 JSON 备份与 DOCX。
- 如果持久化 JSON 损坏或结构非法，应用会先把原始内容保存在独立恢复槽并暂停自动覆盖；请优先下载异常数据，再尝试恢复或确认清空。
- 面试录音文件只保存在本地 `data/recordings` 且已被 Git 忽略；浏览器持久化与 JSON 备份只保存转写、分析结果和录音元数据，不保存音频。
- 已上传录音可在面试复盘页直接播放和删除；仍不提供自动语音转写。

### AI 质量评测

仓库内 `evals/` 保存纯合成冻结案例、确定性评分器和批准的聚合基线，不包含真实简历。`eval:jd` 使用 48 条中文 Gold 案例实际运行原文切片、锚点、稳定 ID、modality 与逐要求召回测试；常规 CI 还会运行案例校验和 Mock 回归。真实模型评测需要在本机明确设置 `CONFIRM_REAL_AI_EVAL=yes` 后手动执行 `npm run eval:ai`，其原始运行结果不会进入 Git。

### 开发者工作台

在“AI 设置 → 高级功能”中开启后，可从顶部进入 `/studio`。工作台展示 TypeScript 产品工作流、提示词与设定、最近 AI 运行追踪、批准的测评基线、可审计开发记录和 Flowise 实验室；不会展示模型隐藏思维链。

“提示词与设定”是只读透明化页面：提示词中心展示系统提示词、用户提示词模板、输出 Schema、模型策略和底层来源；底层文件页可查看仓库内 Markdown 及已注册的 TypeScript 提示词源码；运行快照展示 Provider 适配后模型实际收到的 System/User、Schema、参数和结构修复尝试；版本页显示提示词版本、注册表指纹和测评覆盖。

完整运行快照仅保存在当前浏览器 IndexedDB，最多保留 50 次或 30 天，总量默认不超过 50MB。快照和 Trace 导出包含简历、JD、面试转写等敏感正文，但不会包含 API Key 或 Authorization Header；导出文件请按敏感资料保管。底层文件接口严格只读，`prd/` 等未跟踪 Markdown 可以查看但不会自动提交 Git。

Flowise 不是主业务工作流，只用于可替换 AI 节点实验。详细安装、安全状态、导入流程和本机配置见 [`flowise/README.md`](flowise/README.md)。服务固定为 `http://127.0.0.1:3200`，Playwright 仍使用 `3100`。

工作流页支持受约束调整：可以移动节点、修改说明、开关可选节点，以及设置 AI 节点的 DirectLLM / Flowise / Mock、模型、Prompt 版本、超时和人工确认。材料校验、证据确认、最终简历确认和导出门禁始终锁定。草稿必须先通过结构校验和 Mock 测评；改变执行参数时还需要 7 天内达标的真实模型测评，否则只会生成不影响主流程的实验版本。已发布版本最多保留 10 个，可比较并一键回滚。

Flowise 当前只批准用于“新手项目梳理”实验。因为它的输出 Schema 与简历分析、优化和交付节点不同，把主流程节点设置为 Flowise 仍只会发布为实验版本，不会绕过 TypeScript 执行器或确认门禁。

固定的中文 CID PDF、中文 TTF PDF、多页 PDF 和 DOCX 样本位于 `e2e/fixtures`。需要重新生成时，使用工作区 Python 运行 `scripts/generate_import_fixtures.py`。

## 当前边界

- 扫描版 PDF 暂不支持 OCR；加密或无法读取的文件需改为粘贴文本。
- 视觉还原版 PDF 以 A4 页面图像为主，文本检索请使用 ATS 文字版；系统打印结果仍可能受浏览器打印设置影响。
- 当前为本机个人版，不包含账号、数据库、云同步、职位抓取、自动投递、通知提醒或语音转写。
## V1.10.0 数据版本

材料页可填写目标公司名称与已知岗位背景。分析按“JD 原始条目 → 原子岗位要求 → 已确认事实匹配 → 定向补证 → 逐条面试策略”顺序执行；团队、业务线和汇报关系结论会明确标注为原文明示、有依据推断或信息不足。系统不会联网查询公司，也不会把占位符示范写入事实库或简历。

本版使用业务文档 Schema 11、文档库 Schema 12、备份 V8。旧文档默认没有自定义风格和关键词增强草稿；迁移不会改变原简历、经历证据、模板、投递、复盘或 Studio 数据。
