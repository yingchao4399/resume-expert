# 简历专家评分体系心理测量学审查与重设计报告

> 审查基线：`main`，研究提交前项目版本 `v1.7.2`
>
> 审查日期：2026-08-13
>
> 视角：心理测量学、工业与组织心理学、管理心理学、统计评估与 AI 测评
>
> 边界：本报告审查产品评分设计，不构成对用户人格、心理健康、职业胜任力或录用概率的心理诊断。

## 1. 执行摘要

### 1.1 总体判断

当前项目已经形成七类数值或等级输出：

1. AI 简历诊断 0–100 分；
2. ATS 就绪度及四项子分；
3. JD 证据强度强/中/弱/无；
4. 面试整体表现与维度 0–100 分；
5. 知识掌握度、风险严重度、改进优先级等序数标签；
6. 投递面试率、Offer 率；
7. AI 测评集的 Schema、事实、召回、F1、延迟和发布阈值。

这些输出并不都属于同一种“测量”：

| 类型 | 本项目示例 | 正确解释 |
|---|---|---|
| 工程检查 | Schema 合法、栏目是否齐全、格式能否解析 | 可直接确定，不是心理分数 |
| 形成性指数 | JD 覆盖、证据完整、交付准备 | 多项规则组成的管理指标，权重是政策选择 |
| 序数判断 | 强/中/弱/无、风险高/中/低 | 只能解释顺序，不能默认相邻等级距离相等 |
| 潜在构念测量 | 沟通清晰度、问题解决能力、熟练度 | 需要题目/任务、行为锚点、信效度证据 |
| 预测 | 面试通过概率、Offer 可能性 | 需要真实结局样本、校准和外部验证 |
| 运行评测 | F1、事实保留率、延迟 | 评价 AI 系统，不评价求职者 |
| 描述统计 | 面试率、Offer 率 | 只描述历史记录，不支持因果推断 |

当前最严重的问题不是某个权重差了 5%，而是把这些不同性质的量都包装成同一种 0–100 分。这样会制造三类错觉：

- **精确性错觉**：62 分看起来比 58 分更好，但没有证据证明这 4 分有稳定意义；
- **可比性错觉**：不同岗位、不同模型、不同 JD 得到的 70 分未必是同一尺度；
- **预测错觉**：材料质量、证据覆盖与录用概率是完全不同的推断。

### 1.2 核心结论

- 当前 **AI 简历诊断总分**：心理测量学上不成立，应停止展示总分，先改为带行为锚点的维度画像。
- 当前 **ATS 总分**：可以保留为内部形成性指数，但必须改名为“简历交付准备指数”或拆成独立指标；不能声称模拟真实 ATS，更不能混入用户偏好。
- 当前 **证据强度**：方向正确，但不能把模型给出的强/中/弱/无直接映射为 100/65/30/0 后平均。
- 当前 **面试表现总分**：没有固定构念、题目蓝图、行为锚点和评分者一致性，暂不支持 0–100 分；“通过概率约 40%”应删除。
- 当前 **熟练度**：一次面试中提到某知识点，不能推断个人稳定熟练度；应改为“本次回答中观察到的证据水平”。
- 当前 **投递率**：属于描述统计，方向正确，但状态模型无法重建完整漏斗，分母和不确定性没有展示。
- 当前 **AI 测评指标**：比用户评分更科学，但存在空分母记满分、模拟基线循环证明自身、事实准确率公式命名不实等统计问题。

### 1.3 推荐的最终结构

产品不再给用户一个万能分数，而采用“三层报告”：

```text
第一层：安全与交付门禁
  是否过期 / 是否有事实冲突 / 是否含未确认高风险数字 / 是否可解析

第二层：标准参照画像
  JD 要求覆盖 / 证据完整 / 表达质量 / 格式完整 / 面试回答行为表现

第三层：不确定性与行动
  证据数量 / 评分来源 / 置信区间或一致性 / 最小补证任务 / 与上一版本变化
```

本产品应评价“材料和回答中出现了什么证据”，而不是评价“用户这个人有多少分”。

## 2. 心理测量学如何看待“评分”

### 2.1 先定义推断，再设计分数

心理测量学中的效度不是“这个公式看起来合理”，而是证据和理论是否支持某种分数解释及用途。APA 对效度的定义也强调，效度针对的是从评估中作出的结论是否适当，而不是一个测验天然“有效”。[APA Validity](https://dictionary.apa.org/validity)

因此每个分数都必须先回答：

1. 测什么构念？
2. 对谁、在什么情境下测？
3. 分数用于反馈、排序、筛选还是预测？
4. 分数变化代表真实改善，还是换了 JD、任务、模型或提示词？
5. 错误解释会给用户带来什么后果？

《教育与心理测验标准》把效度、可靠性/精度和公平性作为测试解释的重要基础；EFPA 2025 测验审查模型也要求系统检查工具用途、计分、常模、可靠性、效度和报告质量。[Testing Standards](https://www.testingstandards.net/)、[EFPA Test Review Model 2025](https://www.efpa.eu/resource/efpa-test-review-model-version-2025/)

### 2.2 标准参照优于常模参照

本项目没有代表性求职人群常模，不能解释“你超过 80% 求职者”，也不能把 70 分理解为普遍优秀。

适合本项目的是**标准参照**：

- 是否覆盖某条明确 JD 要求；
- 某项主张是否有可追踪事实；
- 某个数字是否有单位、基线、公式、样本和来源；
- 某个回答是否直接回答问题并说明个人行动。

标准化测验通常还需要代表性常模、统一施测与计分以及经验建立的信效度；当前系统不满足这些条件。[APA Standardized Test](https://dictionary.apa.org/standardized-test)

### 2.3 信度：同样材料能否得到一致结果

可靠性不仅是 Cronbach α。ETS 将其概括为跨时间、跨版本或跨评分者的一致性，并区分重测、复本、评分者一致性、内部一致性、测量标准误和分类一致性。[ETS Reliability](https://www.ets.org/research/policy_research_reports/publications/report/2018/jysw.html)

对本项目，最重要的误差来源是：

- 用户材料版本；
- JD 和岗位族；
- 题目/追问抽样；
- LLM Provider、模型、Prompt 和随机运行；
- 人类专家评分者；
- 用户回答场景与时间。

面试表现等复杂评价应考虑“人 × 问题 × 评分者 × 模型运行”的多误差来源。概化理论可以用方差分解估计这些来源，而单独计算内部一致性可能严重高估可靠性。[Generalizability Theory for Performance Assessment](https://pmc.ncbi.nlm.nih.gov/articles/PMC5058580/)

### 2.4 效度证据框架

本项目至少需要以下五类证据：

| 证据 | 在本项目中的问题 | 推荐方法 |
|---|---|---|
| 内容 | 指标是否覆盖“简历交付准备/回答质量”全部重要方面 | 岗位分析、专家蓝图、CVI/CVR、案例覆盖审查 |
| 反应过程 | 用户和评分者是否按设计理解题目与等级 | 认知访谈、可用性观察、评分者口述与错误分析 |
| 内部结构 | 多个维度是否真能汇总为一个构念 | EFA/CFA；但只用于反映型潜变量，不用于工程清单 |
| 与外部变量关系 | 分数是否与专家判断、工作样本或真实过程有关 | 收敛/区分效度、已知组、增量效度、预测/同期效度 |
| 后果 | 分数是否诱导堆关键词、编数字、焦虑或错误放弃岗位 | 行为实验、用户访谈、错误率和公平性监测 |

量表开发通常包含构念定义、题项生成、专家审查、认知访谈、试测、因子分析、信度与效度验证，而不是先拍一个权重公式。[Scale Development Primer](https://pmc.ncbi.nlm.nih.gov/articles/PMC6004510/)

### 2.5 管理心理学中的岗位相关性

人员评估必须从工作分析出发。OPM 将工作分析定义为系统收集、记录和分析岗位任务、情境与所需能力，它是面试和其他评估工具的基础。[OPM Job Analysis](https://www.opm.gov/frequently-asked-questions/assessment-policy-faq/job-analysis/)

结构化面试之所以比随意印象评分更可靠，是因为：

- 问题来自岗位能力；
- 所有人接受一致问题或受控追问；
- 使用相同评分标准；
- 等级由可观察行为锚定；
- 评分者先独立打分，再处理分歧。

这些原则得到 OPM 结构化面试指南支持。[OPM Structured Interviews](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews)

### 2.6 AI 评分仍要遵守传统测量原则

SIOP 对 AI 人员评估的建议明确指出，AI 评估仍应接受传统人员甄选工具同等级别的审查。[SIOP AI-Based Assessments](https://www.siop.org/wp-content/uploads/legacy/SIOP%20Considerations%20and%20Recommendations%20for%20the%20Validation%20and%20Use%20of%20AI-Based%20Assessments%20for%20Employee%20Selection%20010323.pdf)

NIST AI RMF 同样要求有效可靠、透明可解释、公平、持续测试，并在报告中呈现不确定性和适用边界。[NIST AI RMF](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10)、[NIST Measure](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)

### 2.7 管理心理学的分析框架

本项目真正适用的不是人格测验，而是以下工作与绩效分析框架：

| 框架 | 解决什么问题 | 在本项目中的应用 |
|---|---|---|
| 工作分析 | 岗位到底包含哪些任务、情境和能力 | 将 JD 拆成可追踪 Requirement，并由岗位专家校验 |
| 关键事件技术（CIT） | 哪些具体行为区分有效与无效表现 | 收集优秀、一般和高风险回答，形成行为锚点 |
| 胜任力建模 | 跨任务的知识、技能、行为如何组织 | 建立岗位族能力框架；不能只靠单条 JD 自动决定 |
| 行为锚定评定量表（BARS） | 如何减少“凭感觉打分” | 为简历 finding 和面试回答定义 0–4 可观察行为例子 |
| 结构化面试 | 如何控制问题和评分者误差 | 统一问题蓝图、受控追问、逐题评分和评分者训练 |
| 工作样本 | 如何直接观察真实任务表现 | 将岗位案例、方案拆解或写作任务作为外部效标 |
| 多方法评估 | 单一方法不能覆盖全部能力 | 简历证据、项目材料、面试回答和工作样本互相印证 |
| 现实工作预览 | 降低岗位与候选人预期错配 | 展示岗位情境、约束和风险，而不是只给匹配分 |

最重要的管理心理学原则是：评价标准来自工作本身，而不是来自模型对“优秀候选人”的泛化印象。

### 2.8 统计方法工具箱：什么时候用，什么时候不用

| 方法 | 适用问题 | 本项目建议 | 不能证明什么 |
|---|---|---|---|
| 描述统计 | 当前样本发生了什么 | 计数、比例、中位数、分位数、分组展示 | 不能证明因果或总体规律 |
| 二项区间 | 面试率/Offer 率的不确定性 | Wilson 区间或 Beta-Binomial 可信区间 | 小样本仍不会变成可靠结论 |
| 内容效度 CVI/CVR | 专家认为指标是否相关和完整 | 与定性讨论、蓝图覆盖一起使用 | 不能证明预测效度 |
| 认知访谈 | 用户如何理解题目和反馈 | Think-aloud、追问、错误分类 | 不能替代大样本统计验证 |
| 项目分析 | 哪些题目区分度、难度和反应异常 | 面试题/训练题成熟后使用 | 不适合只有一个自由文本任务的系统 |
| EFA | 潜在维度尚不确定 | 在独立探索样本使用 | 不能靠一次 EFA 确认理论 |
| CFA/SEM | 假设维度结构是否成立 | 在独立验证样本使用 | 不适合把形成性清单强行做成单因子 |
| McDonald ω/α | 同一反映型构念题项的一致性 | ω 优先，α 作补充 | 高值不等于效度，也不覆盖评分者/题目误差 |
| 重测/复本信度 | 跨时间或版本稳定性 | 稳定构念可用；成长反馈需区分真实变化 | 不适合期望短期改变的学习结果直接套用 |
| Kappa | 类别/序数评分者一致性 | 序数等级用加权 kappa | Pearson 相关高不等于评分一致 |
| ICC | 连续评分者一致性 | 明确 ICC 类型和单次/平均评分 | 不能忽略样本、评分者设计和置信区间 |
| 概化理论 | 人、题、评分者、模型运行多误差源 | 面试和 LLM 评分优先方法 | 需要有意设计交叉或嵌套数据 |
| IRT/Rasch | 题目难度与能力水平、不同量尺精度 | 题库规模和样本成熟后再用 | 当前少量开放题不具备使用条件 |
| 测量不变性/DIF | 不同群体分数是否同义 | 跨岗位族、阶段、语言与群体检查 | 统计不变性不是全部公平性 |
| 敏感性分析 | 权重或映射变化会否改变结论 | 对 ATS/交付指数多套权重、映射和阈值重算 | 不能替代权重价值判断 |
| Bootstrap | 指标、F1、效度系数的不确定性 | 对小型测评集报告区间 | 重抽样不能修复有偏或不代表性的案例集 |
| 回归/多层模型 | 控制岗位、渠道、公司和时间后看关系 | 投递样本充足后使用，岗位/公司可作层级 | 观察数据很难证明简历版本造成结果 |
| ROC/PR 与决策曲线 | 二分类阈值及错误成本 | 补证、风险发现、发布门槛 | AUC 高不代表概率校准或公平 |
| Brier/log loss/校准曲线 | 预测概率是否可信 | 只有积累真实结局后使用 | 没有基准率时不能生成“40%” |
| 标准设定 | 哪个等级触发何种行动 | 改良 Angoff、borderline、专家共识 | 不能把专家阈值说成自然真理 |
| 纵向响应性 | 分数是否能检测真实改善 | 面试训练与材料迭代成熟后验证 | 前后分变化可能来自题目/模型变化 |

统计方法的选择必须服从评分用途和数据生成过程。不能因为“心理测量常用 CFA/α”就对所有项目指数都计算一遍；错误地使用高级统计并不会让分数变科学。

## 4. 逐项心理测量审查

## 4.1 AI 简历诊断分

### 当前问题

1. **构念不固定**：模型可自由生成 `dimensionScores.dimension`，两次运行可能测量不同内容。
2. **没有题目或可观察单位**：模型直接从全文跳到分数，没有 finding 到维度的计分链。
3. **没有行为锚点**：只规定 0–100 范围，没有说明 48、58、70 分别意味着什么。
4. **没有总分公式**：`overallScore` 不是由维度分计算，可能和维度不一致。
5. **没有可靠性证据**：未测模型重复运行、Provider、Prompt、岗位和评分者变化。
6. **颜色阈值任意**：50、70 直接映射红黄绿，没有标准设定研究。
7. **标签误导**：UI 的 `ScoreRing` 显示“匹配度”，但页面描述是简历诊断，两种构念被混用。

### 心理测量结论

**不支持继续展示总分。** 当前数值应视为一次模型印象，不是测量分数。

### 重设计

先改为五个固定、标准参照维度：

| 维度 | 评价对象 | 0–4 行为锚点摘要 |
|---|---|---|
| 岗位相关表达 | 简历内容与 JD | 0 无关；1 仅术语；2 有相关经历；3 关键要求有证据；4 重点清晰且证据充分 |
| 事实与证据 | 简历主张 | 0 冲突/虚构风险；1 多数无来源；2 部分支持；3 关键主张可追踪；4 关键主张与数字均可复核 |
| 成果表达 | Bullet | 0 无可理解内容；1 仅职责；2 有行动对象；3 有行动与影响；4 影响有可信口径且边界清楚 |
| 信息结构 | 文档 | 0 严重缺失；1 难扫描；2 基本可用；3 重点清晰；4 针对岗位且冗余受控 |
| 风险与清晰度 | 文档 | 0 有重大冲突；1 多处夸大/歧义；2 有明显风险；3 风险较少；4 无未处理高风险发现 |

模型只输出 `finding`、来源位置和建议；本地规则把 finding 映射到等级。验证前只展示维度等级和证据，不生成总分。

## 4.2 ATS 就绪度

### 当前公式

```text
总分 = 关键词覆盖 × 40%
     + 证据强度 × 30%
     + 含数字 Bullet 比例 × 20%
     + 栏目完整比例 × 10%
```

### 合理之处

- 公式确定、可复现；
- 四个子项可展开；
- UI 已明确“估算”而非保证通过；
- 与模型自报分相比，更适合做产品内反馈。

### 主要效度问题

1. **构念污染**：代码把 `highlightSkills` 拼入简历文本，用户希望强调但没有写入的词也得分。
2. **内容效度不足**：JD 关键词由模型产生，未区分 must/preferred、同义词、否定、年限和上下文。
3. **无关方差**：短关键词、重复词和措辞变化会影响分数，但不代表更适合岗位。
4. **证据分来源不可靠**：证据等级本身是模型标签，再被强制映射为间隔分数后平均。
5. **量化分构念错误**：“有数字”不等于“成果可信”，日期、版本号和随意百分比都可能得分。
6. **完整度一刀切**：九项等权，校招生、转行者和资深人员的必要栏目不同。
7. **权重未经论证**：40/30/20/10 是管理政策权重，不是经验效度权重。
8. **总分掩盖门禁**：一个有事实冲突的简历可能靠关键词和数字得到较高总分。

### 心理测量结论

它不是反映某个潜在能力的心理量表，而是一个**形成性复合指数**。形成性指标不要求各子项高度相关，也不适合用 Cronbach α 证明可靠；应验证的是内容覆盖、权重敏感性、分类一致性和实际决策后果。

### 推荐拆分

不再叫“ATS 总分”，拆成四个互不替代的结果：

1. **格式与解析检查**：通过/警告/阻断；
2. **JD 要求证据覆盖**：按 Requirement 显示 supported/mentioned/missing/conflicting；
3. **事实与数字完整性**：关键主张可核验比例、冲突数、高风险数字数；
4. **内容完整检查**：根据求职阶段的适用规则展示。

如果产品必须保留一个总览数字，应改名为“交付准备指数”，并同时满足：

- 高风险事实冲突和 stale 状态作为门禁，不能被其他分数抵消；
- 展示子项、规则版本和证据时间；
- 权重经过专家内容评审和敏感性分析；
- 不使用 50/70 作为“差/好”阈值，而由标准设定工作坊建立行动阈值；
- 明确说明它不是候选人能力、真实 ATS 通过率或录用概率。

## 4.3 证据强度

### 当前问题

`strong/medium/weak/none` 是有价值的序数分类，但当前存在三个问题：

- 等级由模型直接判断，没有固定行为锚点；
- `100/65/30/0` 暗含等级之间有精确且不等距的数值距离；
- 多条要求直接算术平均，忽略 JD 要求重要性和“冲突”这种非线性风险。

### 推荐行为锚点

| 状态 | 定义 | 是否允许进入最终表述 |
|---|---|---|
| conflicting | 与确认事实、时间、角色或数字冲突 | 阻断，必须处理 |
| none | 没有相关事实 | 不支持该主张 |
| mentioned | 只有自述/术语/学习记录 | 可作为兴趣或接触经历，不可升级为业绩 |
| supported | 有明确场景、个人行动或产出 | 可谨慎表述 |
| verified | 关键实体、角色、行动和结果均有确认来源 | 可作为核心证据 |

不要把 conflicting 塞进从弱到强的一条直线。报告应分别显示：

- 必须要求支持率；
- 优先要求支持率；
- 已验证覆盖率；
- 仅提及比例；
- 缺失数量；
- 冲突数量。

若需要汇总覆盖指数，可以将等级转换为政策分值，但必须保留原始分布，且进行不同映射方案的敏感性分析。

## 4.4 面试表现评分

### 当前问题

1. 模型自由决定 4–6 个维度，无法跨面试比较；
2. 没有按问题逐题评分，整体印象容易产生光环效应；
3. 没有行为锚点、题目难度和岗位蓝图；
4. 单次 16 分钟样例被用于推断“学习潜力”和“熟练度”，构念外推过度；
5. 只有一个模型评分者，没有重复运行或人类评分者一致性；
6. 总分和维度分没有明确聚合关系；
7. 50/70 红黄绿阈值没有依据；
8. `resultPrediction` 给出约 40% 通过概率，却没有历史基准率和校准数据。

### 心理测量结论

当前输出适合作为**质性复盘草稿**，不支持个体能力分数或录用概率。

### 推荐结构化评分

每道题使用固定六维 0–4 行为锚点：

| 维度 | 0 | 2 | 4 |
|---|---|---|---|
| 问题回应 | 未回答/偏题 | 回答主要问题但有遗漏 | 直接完整回答并处理约束 |
| 结构清晰 | 难以理解 | 有基本顺序 | 结构简洁，逻辑和重点清晰 |
| 个人贡献 | 无法区分团队/个人 | 说明部分职责 | 清楚说明角色、决策、协作和边界 |
| 事实证据 | 明显冲突或编造 | 有事实但证据/口径不全 | 关键主张、数字和来源可解释 |
| 岗位相关 | 与要求无关 | 有一般相关性 | 明确连接岗位场景与能力要求 |
| 追问稳健 | 追问后矛盾/失真 | 能补充部分细节 | 能解释取舍、限制、失败和替代方案 |

评分流程：

1. 题目来自固定 JD Requirement 和岗位蓝图；
2. 先按题独立提取观察证据；
3. 再按行为锚点评分；
4. 标记“无法判断”，不得用中间分代替缺失；
5. 同时保存原回答、证据片段、评分者和 rubric 版本；
6. 至少覆盖多个题目后才给维度均值；
7. 在可靠性验证前，不给总分和通过概率。

结构化面试使用统一问题、评分标准和行为锚点，通常比低结构整体印象更有评分者一致性和岗位相关效度。[OPM Structured Interview Research](https://www.opm.gov/policy-data-oversight/assessment-and-selection/other-assessment-methods/structured-interviews/)

## 4.5 熟练度、知识掌握与心理学建议

### 熟练度

一次面试中一个问题回答不好，只能说明“这次回答未展示出足够证据”，不能证明稳定能力水平低。建议区分：

- `selfLevel`：用户自评；
- `evidenceLevel`：职业资产中确认项目支持的水平；
- `observedInSession`：本次回答观察到的行为；
- `notObserved`：没有足够问题/材料，不能评分。

推荐 0–4 行为标尺仍可保留，但每级要绑定最低项目和事实证据，且不得由一次 LLM 输出自动认证。

### 心理学复盘建议

当前页面的“心理学复盘建议”容易让用户误解为心理评估。建议改名为“应对与练习建议”，并遵守：

- 不推断人格、焦虑障碍、心理健康或潜意识；
- 只根据用户明确表达的情境提供一般性练习；
- 清楚区分观察、可能解释和建议；
- 方法论名称不能替代个体化证据；
- 高风险心理状态不由简历产品诊断。

## 4.6 投递率与 Offer 率

### 当前合理之处

- 页面已经声明统计不代表因果；
- 公式可复现，适合作为个人过程记录。

### 当前统计问题

- 数据只有“当前状态”，没有状态事件历史；结束状态无法知道曾否进入笔试/面试；
- 面试率分子只统计当前为面试或 Offer 的记录，会漏掉面试后结束的记录；
- Offer 率分母包含哪些已结束/撤回/未回复场景不清楚；
- 小样本直接显示整数百分比，会制造巨大稳定性错觉；
- 不同岗位族、渠道、时期和简历版本混合，存在混杂；
- 用户主动记录的岗位不是随机样本，不能外推到市场。

### 推荐展示

- 同时显示分子/分母，例如 `2/7（29%）`；
- 样本少于 5 时优先显示计数，不突出百分比；
- 保存状态事件时间线，计算真实阶段转化与停留时间；
- 给比例展示 Wilson 区间或 Beta-Binomial 可信区间；
- 只有达到合理样本并控制岗位族/渠道/时间后，才比较版本差异；
- 明确禁止解释为“某简历导致 Offer”。

## 4.7 AI 测评集指标

### 当前优势

- 使用合成案例，不提交真实简历；
- 将 Schema、事实、JD 召回、补证判断和证据强度分开；
- 使用 F1 处理补证检测，优于只看准确率；
- 真实模型评测与普通 CI 分离；
- 有失败类型和延迟指标。

### 关键统计问题

1. **Mock 基线循环证明**：Mock 输出直接从案例 expected 构造，24 项 100% 只能证明评分器能读回答案，不能证明产品模型质量。
2. **Schema 指标混合**：malformed-output 被正确拒绝时计为 `schemaValid=1`，把生成端 Schema 合法率和验证器拒绝能力混成一个指标。
3. **空分母满分**：`safeRatio` 默认空分母为 1，会让没有可评价事件的案例自动得到完美分。
4. **Macro-F1 可能虚高**：某证据等级在样本中完全缺席时，其 F1 可能按 1 计入宏平均。
5. **事实准确率命名不成立**：`retention × (1 - unsupportedRate)` 是自定义复合指数，不是标准 accuracy；且 forbidden list 不可能穷尽模型所有无依据主张。
6. **字符串包含过于脆弱**：事实保留和禁用主张只做子串判断，不能识别同义改写、否定和数字语义变化。
7. **发布阈值任意**：20 个案例、95%/90% 阈值未给出风险或置信区间依据。
8. **Studio 硬编码基线**：固定显示 100%，没有读取真实基线文件和不确定性。

### 推荐指标重构

| 目标 | 推荐指标 | 备注 |
|---|---|---|
| 输出结构 | 生成 Schema 合法率、修复成功率、验证器拒绝灵敏度/特异度 | 三者分开 |
| 事实保留 | Claim-level recall | 关键事实未保留的风险 |
| 无依据生成 | Claim-level precision、unsupported claims per 1,000 chars | 需要事实原子与专家标注 |
| JD 要求 | 必须/优先 requirement recall、precision、nDCG | 排序也要评价 |
| 补证判断 | precision、recall、F1、混淆矩阵 | 依据错误成本确定阈值 |
| 证据等级 | weighted kappa、macro-F1、逐类 precision/recall | 序数标签优先加权 kappa |
| 模型稳定 | 同案例重复运行一致率、ICC/weighted kappa | 跨模型、Prompt、时间 |
| 概率输出 | Brier score、log loss、校准曲线 | 未校准前不显示概率 |
| 运行质量 | p50/p95 延迟、失败率、Token | 与内容质量分开 |

所有比例和 F1 都应给 bootstrap 置信区间；空分母输出 `NA`，不能自动记满分。

## 5. 推荐的评分总体架构

## 5.1 先把“人”和“材料”分开

产品文案应遵循：

- 不说“你的能力只有 48 分”，而说“本次材料未展示该要求的充分证据”；
- 不说“面试表现差”，而说“这 3 道题中，个人贡献和数据口径说明不足”；
- 不说“匹配度 70 就适合”，而说“10 条必须要求中，6 条有支持证据、2 条仅提及、2 条缺失”；
- 不用红色惩罚用户缺少本来就没有的经历，使用“缺失/待核实/有冲突/已支持”。

这能减少全局标签、锚定效应、防御反应和为分数而堆词/编数字的 Goodhart 风险，也更符合发展性反馈的目的。

## 5.2 四个独立评分域

### A. 简历交付安全门禁

不计总分，只输出状态：

- `blocked`：过期、存在未处理事实冲突、关键实体缺失、未确认高风险主张；
- `review`：有未核验数字、低证据关键表述或格式警告；
- `ready`：门禁通过，可以导出，但不代表会通过招聘筛选。

### B. JD 证据覆盖画像

逐条 Requirement 展示：重要性、证据状态、引用事实、风险和下一步。汇总只显示：

```text
必须要求：已验证 3 / 已支持 2 / 仅提及 1 / 缺失 2 / 冲突 0
优先要求：已验证 1 / 已支持 2 / 仅提及 2 / 缺失 1 / 冲突 0
```

可以附一个“加权支持率”，但不能替代分布。

### C. 简历表达质量画像

采用第 4.1 节五维 0–4 行为锚点。每个维度显示：

- 当前等级；
- 支持等级的 finding；
- 无法判断项；
- 最小改进动作；
- 评分者/模型和 rubric 版本。

### D. 面试回答质量画像

采用第 4.4 节六维逐题评分。会话层只汇总已实际抽到题目的结果，并显示题数、题目覆盖与不确定性。

## 5.3 推荐数据结构

```ts
interface AssessmentContext {
  assessmentId: string;
  constructId: string;
  intendedUse: "coaching" | "quality-control" | "model-evaluation";
  targetRole: string;
  jobFamily: string;
  careerStage: string;
  sourceRevision: string;
  rubricVersion: string;
  scorerType: "rule" | "human" | "llm";
  scorerVersion: string;
  scoredAt: string;
}

interface AnchoredRating {
  dimensionId: string;
  level: 0 | 1 | 2 | 3 | 4 | null;
  status: "observed" | "not-observed" | "conflicting";
  evidenceIds: string[];
  rationale: string;
  confidence: "low" | "medium" | "high";
}

interface AssessmentReport {
  context: AssessmentContext;
  gates: Array<{ id: string; status: "pass" | "warn" | "block"; evidenceIds: string[] }>;
  ratings: AnchoredRating[];
  limitations: string[];
  nextActions: string[];
}
```

`confidence` 不是模型主观自信，而由证据数量、来源质量、评分者一致性和模型重复一致性共同决定。

## 6. 统计验证方案

## 6.1 阶段一：构念与内容效度

### 方法

1. 为每个评分域写清 intended use 和禁止解释；
2. 对 4–6 个典型岗位族做工作分析；
3. 建立 JD Requirement、简历 finding 和面试题蓝图；
4. 邀请招聘、业务、职业咨询和测量专家评审相关性、完整性和可理解性；
5. 计算 CVI/CVR 作为辅助，不用一个阈值取代专家讨论；
6. 对校招、转行、初中高级社招用户做认知访谈，检查“证据”“熟练”“准备度”等词的理解。

建议初期使用 6–10 名跨角色专家，覆盖至少 4 个岗位族；每个主要用户群进行约 8–15 次认知访谈，直到主要误解不再新增。样本数是起始规划，不是普遍充分性证明。

## 6.2 阶段二：评分者训练与一致性

### 标注设计

- 建立 100–200 个合成或脱敏材料单元；
- 每个单元至少由两名评分者独立评分；
- 20%–30% 由第三名资深专家复核；
- 评分前使用典型、边界和反例做 frame-of-reference training；
- 记录分歧原因，而不只保存最终共识标签。

### 统计方法

- 序数等级：加权 Cohen/Fleiss kappa；
- 连续汇总：ICC，并明确模型、单次/平均评分和绝对一致/一致性类型；
- 缺失或多评分者复杂场景：Krippendorff α 可作补充；
- 分类门禁：一致率、灵敏度、特异度、分类一致性；
- LLM：同材料重复 3–5 次，评估 run-to-run 一致性。

普通相关系数不能替代评分者“绝对一致”；kappa/ICC 的选择必须对应数据类型和决策用途。[Inter-rater Reliability and Kappa](https://pmc.ncbi.nlm.nih.gov/articles/PMC3900052/)

## 6.3 阶段三：内部结构与可汇总性

只有当维度被理论上定义为某个共同潜在构念的反映时，才做 EFA/CFA。若“岗位相关性、证据、结构、风险”共同**形成**交付质量，它们不必高度相关，不能因为 α 低就删掉重要维度。

若未来要形成“面试回答质量”总分：

1. 先在独立样本探索维度结构；
2. 再用 CFA 验证；
3. 检查维度是否足够单一或需要多维报告；
4. 使用 McDonald ω，不把 α 当唯一证据；
5. 给出测量标准误或 bootstrap 区间；
6. 验证跨岗位族、求职阶段和语言的测量不变性。

现代量表研究建议用 CFA 验证假设结构，并通过测量不变性检验判断不同群体中的分数含义是否相同。[Psychological Scale Best Practices](https://pmc.ncbi.nlm.nih.gov/articles/PMC11798685/)

## 6.4 阶段四：效标与增量效度

效标分层：

| 效标 | 优先级 | 局限 |
|---|---:|---|
| 资深招聘/岗位专家的结构化判断 | 高 | 仍有人类评分偏差 |
| 结构化工作样本表现 | 高 | 成本较高，但最接近实际行为 |
| 面试题行为评分 | 中高 | 受题目和评分者影响 |
| 是否进入面试/Offer | 中 | 强烈受公司、市场、渠道和样本选择影响 |
| 用户主观满意度 | 低到中 | 反映体验，不等于测量有效 |

研究问题不应只是“分数与 Offer 是否相关”，还应问：

- 新评分是否比简历完整度等简单基线增加解释力？
- 在控制岗位族、年限、渠道、时间和公司层级后还有多少增量？
- 分数对不同群体的含义是否一致？
- 错误地判为“准备好”与错误地判为“未准备好”的代价分别是什么？

## 6.5 阶段五：阈值与标准设定

当前 50/70 阈值应撤下。新的阈值应根据用途建立：

- 安全门禁：由风险规则直接决定；
- 行为等级：由专家给出边界案例和锚点；
- 准备状态：可采用改良 Angoff、borderline group 或专家共识，并验证分类一致性；
- AI 发布门槛：由错误成本、最低案例覆盖和置信区间下界共同决定。

阈值附近的测量误差尤其重要。ETS 建议对分类决策报告阈值附近的一致性与测量精度，而不是只给一个点分。[ETS Standards on Reliability and Cut Scores](https://www.tr.ets.org/pdfs/about/standards-quality-fairness.pdf)

## 6.6 阶段六：公平性与后果

本项目不是雇主甄选工具，但评分仍可能影响用户是否申请岗位、如何评价自己，因此需要公平性审查：

- 校招、转行、自由职业、职业空窗者是否因传统栏目设计被系统性低估；
- 中文/英文、技术/非技术岗位是否得到同等稳定的解释；
- 性别化措辞、年龄、学校、公司品牌是否进入本不该进入的评分；
- 模型是否把表达流利误当能力，把缺乏数字误当没有贡献；
- 评分是否诱导编造数字、堆关键词或放弃高成长岗位；
- 是否存在跨群体 DIF/测量不变性问题。

如果未来用于企业筛选，还需开展不利影响和法律合规研究。EEOC 的四分之五规则只是发现潜在不利影响的经验门槛，不是公平性的最终证明。[EEOC Uniform Guidelines Q&A](https://www.eeoc.gov/es/node/130157)

## 7. 推荐的发布与展示规则

### 7.1 用户侧

- 默认展示“状态 + 维度 + 证据 + 行动”，不先展示总分；
- 任何 0–100 分都提供“如何计算”和“不能说明什么”；
- 未验证的量表使用“试验性指标”标记；
- 不显示录用概率、人格判断或心理诊断；
- 对小样本比例显示分子/分母和不确定性；
- 显示与自己的上一版本变化，而不是虚构人群排名；
- 允许用户查看、纠正和拒绝评分依据。

### 7.2 Studio 侧

每个评分版本保存：

- 构念和 intended use；
- rubric、权重和阈值版本；
- 样本构成与排除规则；
- 每类指标及置信区间；
- 人类/模型评分者一致性；
- 跨岗位族与阶段表现；
- 已知局限和禁止用途；
- 与前一版本的差异和回滚条件。

### 7.3 评分变更治理

任何 Prompt、Provider、模型、关键词抽取、权重、等级锚点或事实 Schema 变化，都可能改变分数含义。变更必须：

1. 生成新的评分版本；
2. 在冻结案例上对比；
3. 对关键分歧做人类复核；
4. 检查总体和分组退化；
5. 更新限制说明；
6. 不把新旧分数直接画成连续趋势，除非完成链接/等值验证。

## 8. 对现有评分的处置清单

| 当前输出 | 处置 | 新名称/形式 | 优先级 |
|---|---|---|---:|
| AI 简历诊断总分 | 撤下总分 | 五维行为锚定画像 | 最高 |
| AI 自由维度分 | 固定维度与 finding 链 | 标准参照等级 0–4 | 最高 |
| ATS 总分 | 拆分；必要时保留透明指数 | 交付准备指数 | 最高 |
| 关键词分 | 修复输入污染，升级 Requirement 覆盖 | JD 要求证据覆盖 | 最高 |
| 量化成果分 | 删除“出现数字即得分” | 数字证据完整性 | 最高 |
| 证据强度平均分 | 停止直接平均模型标签 | 状态分布 + 加权支持率 | 最高 |
| 面试表现总分 | 暂停 | 逐题六维行为评分 | 最高 |
| 面试通过概率 | 删除 | 不提供；未来有校准数据再评估 | 最高 |
| 知识熟练度 | 降低推断范围 | 本次回答观察证据 | 高 |

## 9. 推荐实施顺序

本报告不要求立即开发下一版本，但从评分风险看，未来实施应按以下顺序：

### 第 1 批：停止过度解释

- 删除面试通过概率；
- 将 AI 诊断和面试总分标为实验性或暂时隐藏；
- 修复 ATS 偏好污染；
- 移除 50/70 任意红黄绿解释；
- Mock 基线改名为评分器自检。

### 第 2 批：建立评分蓝图

- 固定构念、用途、维度和行为锚点；
- 建立 Requirement、Finding、EvidenceClaim 的计分链；
- 区分 `not-observed`、`missing` 和 `conflicting`；
- 固定人类/LLM 标注协议和版本。

### 第 3 批：开展标注与信度研究

- 专家内容评审和认知访谈；
- 双人标注与评分者训练；
- weighted kappa、ICC、分类一致性；
- LLM 重复运行、跨模型和 Prompt 稳定性。

### 第 4 批：验证与治理

- 外部效标和增量效度；
- 岗位族、阶段、语言的公平性与不变性；
- 阈值标准设定；
- 不确定性、限制和版本差异进入 Studio。

## 10. 最终设计原则

1. **先定义构念，再计算分数。**
2. **效度属于具体解释和用途，不属于一个孤立公式。**
3. **标准参照优先，不虚构常模和百分位。**
4. **工程检查、形成性指数、心理构念、预测概率和运行指标分开。**
5. **序数等级不自动当作等距分数平均。**
6. **模型提取观察和理由，本地规则计分，人类可复核。**
7. **评分必须绑定材料、JD、题目、rubric、模型和版本。**
8. **报告不确定性、无法判断和评分者分歧。**
9. **门禁风险不能被其他高分抵消。**
10. **评价材料与行为证据，不给用户贴全局能力或人格标签。**
11. **反馈必须具体、可控制、可行动，并允许用户纠正依据。**
12. **任何概率必须经过真实结局样本的校准。**
13. **真实投递结果只能支持谨慎相关分析，不轻率宣称因果。**
14. **公平性和使用后果是评分质量的一部分。**
15. **当证据不足时，最科学的输出是“不足以判断”，不是 50 分。**

## 11. 最终结论

当前项目已经具备做严谨评分系统的工程基础：有确定性计算器、事实账本、合成案例、Schema、Trace、版本和 Studio。但现有用户侧评分总体仍处于“产品启发式”阶段，不属于经过心理测量验证的测评工具。

最值得保留的是“可展开、可行动、与证据连接”的方向；最需要放弃的是“一个漂亮的 0–100 数字可以代表岗位匹配、面试能力或通过概率”的想法。

从心理测量与管理心理学角度，最好的简历评分系统不是把人压缩成一个分数，而是帮助用户准确回答三件事：

> 我现在的材料展示了什么？哪些结论有证据？为了这个具体岗位，下一项最值得补充或练习的可观察行为是什么？

这会让评分从装饰性数字，升级为可信的职业发展反馈系统。
