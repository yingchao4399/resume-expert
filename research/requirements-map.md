# 需求地图（研究草案）

## 1. 核心用户闭环

```text
原始材料
→ 经历 / 项目 / Demo 结构化梳理
→ 能力与证据绑定
→ 目标岗位逐条要求解析
→ 缺口驱动的自适应追问
→ 可核验的简历素材
→ 岗位版本与面试训练
→ 投递反馈
→ 个人素材库与作品集沉淀
```

核心对象不是“简历文本”，而是可以被多个岗位版本复用、可追溯来源的 `CareerAsset`。

## 2. 信息分层

| 层级 | 例子 | 是否可直接写入简历 | 规则 |
|---|---|---:|---|
| 用户确认事实 | 公司、岗位、时间、做过的动作、可复核数字 | 是 | 必须有来源或用户确认 |
| 用户自评 | 熟练度、偏好、未来方向 | 有条件 | 必须标记为自评，不能伪装为业绩 |
| 公开企业事实 | 工商、融资、诉讼、官网、招聘数量 | 通常否 | 必须带来源和采集时间 |
| 公开信号 | 新闻、招聘变化、展会、公众号内容 | 否 | 可用于求职判断或提问，不等于公司内部事实 |
| 系统推断 | 团队痛点、工作重心、隐性期望 | 否 | 必须显示依据、置信度和替代解释 |
| 主观评价 | 氛围、领导偏好、同事关系、欠薪体验 | 否 | 只允许实名公开来源或用户自述，不由模型编造 |

## 3. 能力模型

建议使用“标签 + 可观察行为 + 证据 + 情境”，而不是只有技能词和星级。

```text
Capability
├─ canonicalName       规范名
├─ aliases[]           同义词
├─ category            行业 / 职能 / 工具 / 通用能力
├─ proficiency         自评等级
├─ proficiencyBasis    等级行为标尺
├─ evidenceLinks[]     关联项目、经历、数字、附件
├─ targetRoleDemand    目标岗位要求等级
└─ confidence          系统对证据充分度的判断
```

熟练度初版建议使用 0–4 级：

| 等级 | 行为标尺 |
|---|---|
| 0 未接触 | 无实践证据 |
| 1 了解 | 能解释概念，在指导下完成局部任务 |
| 2 可独立应用 | 在常见情境独立完成并处理一般问题 |
| 3 熟练 | 多次交付，能权衡方案、解决复杂问题、指导他人 |
| 4 专家 / 负责人 | 建立方法、跨团队规模化、对业务结果负责 |

等级不能只靠用户点击，系统应根据关联证据提出校验问题，但最终仍由用户确认。

## 4. 项目 / Demo 结构化拆解

建议统一为 `ProjectAsset`，支持增删、复制、归档与版本：

- 背景与业务问题
- 目标与成功标准
- 用户 / 客户 / 利益相关者
- 个人角色、边界与协作者
- 关键约束
- 决策与方案
- 具体行动
- 产出物与链接
- 结果、数字及计算口径
- 失败、权衡与复盘
- 能力标签与证据链接
- 面试一句话版本、2 分钟版本、深挖版本
- 事实状态：草稿 / 待确认 / 已确认 / 有争议

## 5. 岗位与公司情报分层

`JobTarget` 应拆成：

- JD 原文与逐条 `Requirement`
- 公司 / 团队背景（用户输入或公开来源）
- 公司规模、阶段、地点、工作方式、待遇范围
- 公司公开身份与工商情报引用
- 招聘与业务信号
- 用户个人偏好与红线
- 系统推断的团队痛点、工作重心、汇报关系及置信度

公司背调不应直接塞进 `ResumeDocument`，应作为独立、有来源、带有效期的 `CompanyResearchSnapshot`。

## 6. 技术初判

| 能力 | 固定 TypeScript 工作流 | Skill | RAG | 数据库 |
|---|---:|---:|---:|---:|
| 材料校验、证据门禁、评分 | 必须 | 可辅助 | 不需要 | 结构化存储需要 |
| 自适应经历访谈 | 编排与门禁 | 非常适合 | 可选 | 需要保存会话与事实 |
| 能力标签归一化 | 规则为主 | 可辅助 | 适合检索 ESCO/O*NET 等词表 | 需要标签关系 |
| JD 逐条解析 | Schema 与校验 | 适合 | 可选 | 需要版本化要求 |
| 公司公开情报 | 采集规则与来源门禁 | 适合按源抓取 | 适合检索快照 | 强烈需要来源数据库 |
| 简历生成与导出 | 必须 | 不应接管 | 不需要 | 复用业务数据 |
| 作品集生成 | 固定模板与隐私门禁 | 可辅助 | 从个人素材检索 | 需要素材/附件索引 |

初期不要把整个产品迁到 Dify / Flowise。主流程、数据迁移、评分和写入门禁继续由 TypeScript 控制；Skills 或 Flowise 只负责可替换访谈和研究节点。

## 7. 第一轮需求取舍

### P0：直接形成产品差异化

- 个人素材库：项目 / 经历 / Demo / 能力 / 数字证据统一建模
- 岗位要求逐条解析与逐条证据匹配
- 不知道怎么回答时的分层提示、示例与回答评审
- 数字口径、证据状态和风险检测
- 目标岗位需要突出能力 vs 用户希望突出能力分开
- 评分标准、计算过程和证据链可解释

### P1：形成持续使用闭环

- 项目匹配排序
- 面试回答框、对比、评分、证据准备
- 教育、课程、绩点、证书、继续教育的条件化展示
- 投递结果回流个人素材库
- 作品集素材沉淀

### P2：外部情报扩展

- 公司公开情报与来源快照
- 招聘趋势、新闻、展会、公众号、知识产权、诉讼等公开信号
- 用户自定义公司类型、规模和阶段

### 不应承诺或自动推断

- HR 私人背调、领导人格或喜好
- 同事、客户、上下级关系的确定结论
- 年终奖、分红、加班、欠薪等缺乏可靠来源时的事实判断
- 未公开融资、财务和团队规划
