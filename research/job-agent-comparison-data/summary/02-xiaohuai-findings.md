# 小坏简历专项归纳

> 事实依据见 [`raw/02-xiaohuai-resume-site.md`](../raw/02-xiaohuai-resume-site.md)。

## 产品定位判断

小坏简历不是单纯的简历生成器，而是把两种用户任务包装成两条产品线：

- **Studio**：用户已经有简历，目标是诊断、扩写、确认和导出。
- **包装老师**：用户经历零散或不足，目标是素材挖掘、经历大纲、成稿、审批和面试备战。

这比按技术模块组织页面更符合用户心智。Resume Expert 虽然已经具备导入、项目访谈、事实库和最终编辑，但入口仍偏“功能菜单”，缺少一次明确的任务分流和跨流程交接。

## 最值得借鉴

1. **双入口**：先问用户是“优化已有简历”还是“从零梳理经历”，再展示相关工作流。
2. **大纲先行**：AI 先提出经历方向和理由，用户选择后再生成内容，降低长输出跑偏和浪费。
3. **六步产物轨道**：每一步都产生可见产物，而不是只显示 Agent 正在运行。
4. **从访谈交接到 Studio**：结构化事实和项目确认后，一键进入最终简历制作，不要求用户理解底层数据模型。
5. **敏感主张审批**：把新增数字、职责和工具集中成一张导出前清单，逐条批准或拒绝。
6. **面试负债**：识别简历中可能被深问但证据不足的主张，并关联可能追问和诚实答法。
7. **多 JD 分支**：同一事实底座衍生少量岗位分支，显示独立就绪度，而不是复制出失去血缘关系的文档。
8. **导出物组合**：简历、审计报告和面试手册形成一套交付包。

## 不应照搬

- 不照搬“多 Agent + Skill”营销命名；必须先定义产物、门禁、失败语义和测评。
- 不照搬一个不透明的 Job-Ready 总分；Resume Expert 应展示证据覆盖、风险和计算口径。
- 不照搬固定生成的近期购买动态。
- 不采用带威吓感的开发者工具弹窗；任何遥测都应在隐私说明中透明列出并允许关闭。
- 不把课程、源码销售和简历工作台混在主导航中；当前项目应保持职业工作台定位。
- 不强制微信登录或云端保存；当前本机个人版的隐私边界仍然有价值。

## 对路线的影响

原报告偏向先补岗位机会层。加入小坏简历后，建议在其之前先做一个更小但更直接的体验版本：

`任务分流 → 项目/经历大纲确认 → 事实审批 → 交接制作 → 面试负债`

这能复用当前已有的数据和工作流，成本低于招聘平台连接器，也更快体现产品差异。岗位机会收件箱、交付授权和平台连接器继续作为后续版本。
