# 后续建设验收矩阵

## V1.7.3 可信度修复

| 验收项 | 权威证据 |
|---|---|
| 修改 JD 后旧分析不能继续使用 | E2E：分析后修改 JD，所有分析/生成节点显示过期，Finalize 被阻止 |
| ATS 不受用户偏好字段影响 | 单测：只修改 `highlightSkills`，ATS 分数与关键词命中不变 |
| Mock 不引入新事实 | 冻结案例：输出实体、日期、数字集合均为输入集合子集或明确占位 |
| 人工修改后证据需复核 | 单测与 UI：修改实体/数字后 link 状态变为 `needs-review` |
| 证据变更触发依赖过期 | 依赖图单测 + 导出门禁 E2E |
| 备份合并外键正确 | 完整对象图导出/合并/重新导出深度比较 |
| 损坏恢复不静默丢全局数据 | 多分区损坏样本，恢复预览逐区显示保留/丢弃数量 |
| 候选幂等 | 同 question/run 重复生成，candidate 数量不增加或形成修订链 |

## V1.8.2 JD 与定向访谈

| 验收项 | 权威证据 |
|---|---|
| 逐条要求有原文锚点 | 每条 Requirement 可定位到 JD 片段；无法定位时明确标记人工/推断 |
| 事实与推断分离 | 推断必须有 basis/confidence/alternatives，不能显示为 JD 原文 |
| 项目排序可解释 | 固定输入返回稳定排序和分项得分；用户可覆盖 |
| 追问动态停止 | 覆盖、无新增信息、上限、用户暂停四类停止条件均有测试 |
| 示例不污染资产 | 点击示例不会创建 claim；只有用户编辑并确认后产生候选事实 |

## V1.9.x 训练与反馈

| 验收项 | 权威证据 |

## V2.0 公司公开研究

| 验收项 | 权威证据 |
|---|---|
| 主体消歧 | 同名公司样本必须先确认主体，未确认禁止合并来源 |
| 每条结论有来源 | 无 source ID 的内容只能进入推断或未知项 |
| 来源时效 | 过期快照明确提示，刷新不覆盖旧版本 |
| 冲突不被吞掉 | 相反来源并列展示并进入 conflicts |
| 主观样本受控 | 评价显示来源、日期、样本量和非事实提示 |
| 隐私边界 | HR/领导私人画像、敏感属性和无来源指控均被 Schema/策略阻止 |

## 全版本通用门槛

- lint、类型检查、单元测试、生产依赖审计、生产构建和 Playwright 全部通过；
- 迁移与备份测试覆盖上一个正式版本；
- AI 输出均经过 Zod 校验，一次修复失败后给出可操作错误；
- API Key、附件原文件、录音、Trace、Flowise 凭据和真实简历不进入 Git；
- 所有真实数据写入都有用户确认或确定性本地操作；
- 评分、推断和建议都能展开查看依据与限制；
- 每个阶段提交、推送、CI 全绿后才创建 annotated tag。
