# V1.9.5 JD 决策地图实施记录

## 决策

V1.9.5 不再把模型一次生成的 JD 摘要直接作为下游事实。运行链路改为：

`JD 原文 -> 可审核草稿 -> 用户确认 revision -> 逐要求事实匹配 -> 确定性岗位准备度`

TypeScript 负责原文跨度、稳定 ID、明确必须/优先/否定词、引用覆盖、事实外键、证据强度和准备度公式。模型只负责原子化语义草稿、岗位假设和事实相关性解释。

## 可信门禁

- 只有引用合法且原文明示语气的安全项可以批量确认。
- 其他要求必须逐条确认、修改或拒绝。
- 分类为岗位要求的原文必须至少被一条已确认 atom 覆盖。
- 匹配任务同时校验材料 revision 与 JD revision；任一变化都拒绝迟到结果。
- 原简历文字引用最多计为弱证据；中强证据必须来自已确认结构化事实。
- 每条要求独立召回最多 3 条事实，不再使用全局 Top 12。

## 准备度

要求优先级权重为关键 4、高 3、中 2、低 1；证据值为强 1、中 0.67、弱 0.33、无 0。总分只用于准备决策，并同时展示硬门槛、关键任务、结果证据、指标完整度和高影响未知项。

## 数据兼容

ResumeDocument Schema 9、ResumeLibraryState Schema 10、ResumeBackup V6。V1.9.4 及更早分析保留为只读历史，不伪装成已经人工确认的新需求地图。
